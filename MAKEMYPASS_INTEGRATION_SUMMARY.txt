1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
The VYUHAM'26 website has been updated so that MakeMyPass is the authoritative
platform for event registration and payment processing.

Under this architecture:
• VYUHAM provides the premium event discovery, 3D spherical Fibonacci archive,
  festival atmosphere, mission dossiers, rules, timings, and campus logistics.
• MakeMyPass handles participant registration forms, ticket tiers, payments
  (UPI, credit/debit cards, NetBanking), payment gateway verification, ticket
  issuance, and buyer receipts.
• The existing VYUHAM visual design, 3D event sphere, and mobile-responsive
  experience remain completely intact.
• No payment credentials, UPI details, card numbers, or payment secrets are
  accepted or stored inside VYUHAM.
• No fake MakeMyPass payment APIs have been invented.
• External MakeMyPass registration URLs are used safely with target="_blank"
  and rel="noopener noreferrer".

--------------------------------------------------------------------------------
2. CORE ARCHITECTURAL PRINCIPLES & SECURITY BOUNDARIES
--------------------------------------------------------------------------------
• ZERO SENSITIVE DATA IN VYUHAM:
  Payment credentials, cards, and UPI secrets are never handled by VYUHAM.
• NO ASSUMED/FAKE MAKEMYPASS API:
  All participant transactions are conducted directly on MakeMyPass event pages.
• AUTHORITATIVE TICKET OWNERSHIP:
  MakeMyPass is the single source of truth for payment status and ticket validity.
• SAFE EXTERNAL NAVIGATION:
  All outgoing links use target="_blank" and rel="noopener noreferrer".
• NO BROKEN LINKS:
  Events without a MakeMyPass URL display a clear "REGISTRATION UNAVAILABLE"
  state instead of an invalid or broken link.
• ZERO VITE_* LEAKS:
  No private credentials or backend secrets are exposed to client-side bundles.
• DYNAMIC ADMIN CONFIGURATION:
  Admins can update MakeMyPass URLs in the database or SQLAdmin console without
  code rebuilds or frontend redeployment.

4. AUDIT OF EXISTING REGISTRATION & PAYMENT ROUTES
--------------------------------------------------------------------------------
A full audit of existing routes and their frontend callers was performed before
making modifications:

A. BACKEND ROUTES:
• GET /registrations/config/status & PATCH /registrations/config/status:
  - Purpose: Global festival registration switch in site_settings.
  - Decision: RETAINED (VYUHAM-owned). Controls festival launch readiness.
• POST /registrations:
  - Purpose: Local database record insertion in the `registrations` table.
  - Decision: PRESERVED for internal/admin manual entry and legacy tests.
    Deprecated for public event flows.
• GET /registrations/me:
  - Purpose: Returns user's registration records.
  - Decision: RETAINED (VYUHAM-owned). Used by festival dashboard and certificates.
• GET /registrations/{id} & PATCH /registrations/{id}/status:
  - Purpose: Admin inspection and volunteer check-in status modification.
  - Decision: RETAINED (VYUHAM-owned).
• POST /payments/create & POST /payments/verify & GET /payments/receipt/{ref}:
  - Purpose: Internal/mock payment test endpoints.
  - Decision: PRESERVED without breaking existing test suites. Bypassed by
    the public frontend in favor of MakeMyPass external transactions.

B. FRONTEND CALLERS:
• EventDossierModal.tsx:
  - Previous: Handled local state registration or internal profile redirections.
  - Updated: Displays "REGISTER NOW ↗" anchor button pointing to MakeMyPass.
    Displays disabled "REGISTRATION UNAVAILABLE" when no URL is provided.
• EventDetailClient.tsx:
  - Previous: Contained in-app squad selector and called registrationsApi.register().
  - Updated: Primary CTA points directly to MakeMyPass registration URL.
• src/data/content.ts, src/data/events.ts, src/data/types.ts:
  - Updated: Added `registration_url` and `makemypass_url` fields.
• src/lib/store.tsx:
  - Updated: Dynamically synchronizes `registration_url` and `makemypass_url`
    from backend GET /events into the reactive store.

8. HOW ADMINS CONFIGURE MAKEMYPASS URLS
--------------------------------------------------------------------------------
To set or update a MakeMyPass registration URL for any event:

Option 1: Via VYUHAM Admin Console
  1. Open http://localhost:8000/admin (or production URL).
  2. Authenticate with admin credentials.
  3. Navigate to Events → Click on the event.
  4. Fill in `MakeMyPass Url` or `Registration Url` (e.g. https://makemypass.com/event/slug).
  5. Save. The frontend will immediately use the new link upon next visit.

Option 2: Via SQL / Database Query
  UPDATE events
  SET makemypass_url = 'https://makemypass.com/event/your-event-slug',
      registration_url = 'https://makemypass.com/event/your-event-slug'
  WHERE slug = 'your-event-slug';
